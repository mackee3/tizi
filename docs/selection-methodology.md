# 梯子评估与测速方法

[返回 2026 梯子推荐](../README.md)

本文档说明项目如何区分套餐事实、服务商声明和实际测试，避免把营销文案、单次测速或虚构经历写成客观结论。

## 证据等级

### 套餐页已核验

可以直接从服务商套餐页确认的信息，例如：

- 价格和付款周期；
- 流量与重置规则；
- 标称速率；
- 设备或在线客户端数量；
- 优惠码；
- 退款与换套餐规则。

核验只证明页面曾这样展示，不证明服务质量或未来价格不变。

### 服务商声明

需要明确归因的信息，例如：

- IPLC、IEPL、BGP 或原生 IP；
- 晚高峰不降速；
- Netflix、TikTok、ChatGPT 等解锁；
- 运营团队所在地；
- 在线率、节点数和带宽能力。

在没有独立测试或可靠文件时，正文使用“页面称”“服务商声明”，不写成本站结论。

### 本站实测

只有保留日期、网络、客户端、节点和原始结果的测试，才能标注为本站实测。当前主推荐页尚未发布统一测速排名。

## 推荐顺序

当前推荐顺序主要依据可核验的用户场景，而不是佣金比例：

1. 是否存在月付或小额入口；
2. 套餐价格、流量和设备是否匹配常见需求；
3. 重置、退款和换套餐规则是否清楚；
4. 是否提供不同流量档位或不限时备用方案；
5. 页面声明的系统和客户端支持；
6. 重要限制是否能在推荐位置同时展示。

没有统一测试时，不以“最快”“最稳”作为排序依据。

## 统一测速计划

未来测速至少记录以下字段：

| 字段 | 要求 |
| --- | --- |
| 日期和时间 | 区分普通时段与 20:00–23:00 晚高峰 |
| 本地网络 | 运营商、接入方式、基础宽带速率 |
| 设备和客户端 | 操作系统、客户端版本、连接模式 |
| 套餐和节点 | 套餐名、节点地区、协议、倍率 |
| 延迟 | 多次采样，记录中位数和 P95，而非最低值 |
| 丢包和抖动 | 持续测试，不只看一次连接 |
| 吞吐 | 同一工具多次测试，记录平均值 |
| 可用性 | 网页、下载、视频和目标服务分别记录 |
| 异常 | 超时、断流、DNS、客户端错误和恢复时间 |

### 建议测试矩阵

- 中国电信、中国联通、中国移动分别测试；
- 家庭宽带和手机网络分别测试；
- 工作日与周末各至少一次；
- 白天和晚高峰分别测试；
- 香港、日本、新加坡、美国等常用节点分别测试；
- 连续多日复测，不用单日最高成绩做长期结论。

## 评分边界

在数据不足时不发布精确总分。未来如使用评分，应公开权重，并把稳定性、丢包和长期可用性放在单次峰值速度之前。不同运营商结果差异大时，应分别展示，不合并成一个误导性的平均分。

## 套餐与链接复核

- 套餐资料当前快照日期：2026-08-12。
- 推广短链最近自动检查：2026-08-15。
- 自动检查只能确认 HTTP 响应或跳转，不能证明注册、支付、退款和售后可用。
- 发布前重新核对价格、流量、设备、优惠、品牌名称和入口。
- 发现停服、跳转异常或套餐重大变化时，先降低推荐可见度，再完成复核。

## 不采用的证据

- 无日期、无网络环境的测速截图；
- 无法确认来源的群聊评价；
- 服务商自行制作的排名；
- 为写作而虚构的使用记录；
- 只测试一个节点、一次速度得出的长期结论；
- 佣金比例或合作关系。

对项目内容有更正建议，可以通过 GitHub Issue 提供页面链接、截图日期和具体字段。
